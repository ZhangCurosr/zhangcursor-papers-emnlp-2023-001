# 论文速读：BioPlanner-Automatic-Evaluation-of-LLMs-on-Protocol-Planning

## 一句话总结
本文提出了一种自动评估大型语言模型（LLMs）在生物学实验方案规划任务中能力的方法，通过构建 **BIOPROT** 数据集将自然语言协议转化为伪代码，实现了协议生成能力的客观量化评估，并验证了 GPT-4 生成的方案在实际实验室操作中的可行性。

## 研究问题与动机
1.  **核心问题**：如何自动、准确地评估 LLM 生成科学实验协议的能力？
2.  **现有方法不足 - 文本评估局限**：传统的文本相似度指标（如 BLEU、BERTScore）难以捕捉协议中细微但关键的步骤顺序差异和物质间关系。
3.  **现有方法不足 - 评估粒度与专家依赖**：同一协议可用不同粒度描述，且协议准确性评估通常需要领域专家知识，成本高昂。
4.  **现有方法不足 - 缺乏自动评测基准**：现有 LLM 在科学领域的应用多集中于问答或检索，针对开放式、多步骤的科学规划任务缺乏自动化的评估标准。

## 核心贡献（创新点）
1.  **提出基于伪代码的自动评估框架**：将开放的协议生成任务转化为对结构化伪代码的预测任务，使评估更客观、自动化。*区别于仅依赖文本相似度评估的方法。*
2.  **构建并开源 BIOPROT 数据集**：创建一个包含 100 个经专家审核的生物学协议及其对应伪代码表示的数据集。*区别于以往缺乏标准化评估数据的现状。*
3.  **定义细粒度评估任务与指标**：设计了下一步预测、完整协议生成、函数检索等任务，并提出了函数级准确率、参数级 SciBERTScore 和规范化 Levenshtein 距离等指标。*提供了多维度的能力诊断。*
4.  **实证评估主流 LLM 并探索鲁棒性**：系统评估了 GPT-3.5 和 GPT-4 在协议生成任务上的表现，分析了输入顺序和反馈机制的影响。*揭示了模型在长程规划上的潜力与局限。*
5.  **实现端到端的现实世界验证**：通过检索和组合现有协议的伪代码生成新方案，并在实验室成功执行。*证明了方法的实用价值和生成方案的可靠性。*

## 方法详解
1.  **BIOPROT 数据集构建**：
    *   **来源与筛选**：从 Protocols.io 收集协议，经自动和人工筛选得到 100 个生物学协议（平均 12.5 步）。
    *   **伪代码生成**：使用 GPT-4 将自然语言协议转换为伪代码。首先让模型定义执行协议所需的**伪函数集**（Admissible Actions），然后仅使用这些伪函数生成步骤序列。
    *   **调试与审核**：引入自动反馈循环检测语法错误、缺少参数/单位等问题，并由实验室科学家进行人工审核与修正。
2.  **评估框架设计**：
    *   **角色设定**：“教师”模型（GPT-4）生成伪代码作为 Ground Truth；“学生”模型（待评估的 LLM）根据任务输入（标题、描述、允许的伪函数列表）尝试重建伪代码。
    *   **任务类型**：
        *   **下一步预测**：给定部分伪代码，预测下一步应调用的函数及其参数。
        *   **协议生成**：从标题和描述生成完整的伪代码序列。
        *   **函数检索**：从混合了正确函数和干扰函数的列表中，选出执行协议所需的函数。
    *   **评估指标**：
        *   **函数级准确率**：预测函数是否与 Ground Truth 完全一致。
        *   **参数级评估**：对正确的函数，评估参数名的精确率/召回率，以及参数值的 **SciBERTScore**（语义相似度）和 **BLEU**（词重叠）。
        *   **规范化 Levenshtein 距离**：衡量生成函数序列与正确序列的差异，值越低越好。
    *   **实验设置**：考察了输入函数列表是否被打乱（Shuffle）以及是否使用反馈循环（Feedback）两种条件。

## 实验与结果
1.  **数据集**：BIOPROT，100 个协议。
2.  **基线模型**：GPT-3.5, GPT-4, Llama-2-7B（附录）。
3.  **主要结果**：
    *   **下一步预测（表 4）**：GPT-4 函数准确率（70.6%）高于 GPT-3.5（65%）；函数打乱导致性能下降。
    *   **协议生成（表 5）**：GPT-4 在规范化 Levenshtein 距离上显著优于 GPT-3.5（0.396 vs 0.498），显示其步骤规划能力更强；两者在函数选择的精确率/召回率上相近。
    *   **函数检索（表 6）**：GPT-4 优于 GPT-3.5，但整体表现较差（最高召回率 49.4%），可能源于相似协议函数的干扰。
    *   **GPT-4 评估器（表 8）**：GPT-4 区分自己输出与 Ground Truth 的能力仅略高于随机（~40%），表明生成质量较高。
    *   **人类基准（附录 F）**：人类在函数选择任务上表现远超 GPT-4（精确率 87.5%），但在下一步预测上与 GPT-4 在打乱设置下相当（54.8%）。
4.  **最强结果**：GPT-4 在协议生成任务规范化 Levenshtein 距离上达到 0.396，下一步预测函数准确率达 70.6%。

## 相关工作脉络
1.  **LLM 用于自然科学**：如 Chemcrow (Bran et al., 2023) 展示了 GPT-4 Agent 在化学合成规划中的应用，但缺乏自动评估。*本文定位为填补协议生成任务的自动评估空白。*
2.  **任务分解与规划**：CoT、Tree of Thoughts 等方法通过分解复杂推理提升 LLM 性能。*本文强调先定义离散动作空间再学习组合的策略。*
3.  **LLM 评估基准**：现有科学领域评估多为 QA 任务（如 MMLU, PubMedQA）。*本文首次关注开放式、多步骤的协议生成评估。*
4.  **自动评估 LLM**：常采用自我评估，但可能存在偏见。*本文利用 LLM 在简单子任务的一致性生成基准来评估复杂任务。*
5.  **机器人规划**：通常依赖受限动作空间和模拟环境。*本文无需模拟环境，通过自动生成动作空间进行评估。*

## 局限性与未来方向
1.  **成本与开源模型**：依赖闭源 GPT API 成本较高（约 $1000），需探索开源模型的表现。
2.  **领域扩展**：目前仅限生物学，可扩展至化学、材料科学等。
3.  **安全风险**：存在被用于生成危险化合物合成协议的风险，需加强输出限制。
4.  **评估器性能**：GPT-4 作为评估器的判别能力有限，可能与生成质量过高或判别难点有关。
5.  **任务歧义**：函数检索任务中，语义相同但语法不同的函数可能影响评估公平性。

## 研究启发与可借鉴点
1.  **结构化表示促进自动评估**：将开放文本生成转化为结构化序列（如伪代码、PDDL）生成，可实现更客观的自动评估，适用于机器人操作、化学合成等需要多步推理的领域。
2.  **“教师-学生”评估范式**：利用强模型在简单子任务的高可靠性生成评估基准，进而评估其在更复杂任务上的表现，是一种有效的评估策略。
3.  **细粒度分层评估**：对于工具调用型任务，分离“工具选择”和“参数生成”的评估，能更精准地诊断模型短板。
4.  **自动化调试结合人工审核**：在数据集构建中，结合自动反馈循环纠错和有限的人工关键逻辑审核，能平衡数据质量与标注成本。
5.  **现实世界闭环验证**：将算法产出应用于真实物理世界（如实验室实验）是验证 AI 系统实际效用的高标准方法。

## 关键术语表
*   **Pseudocode**：一种介于自然语言和编程语言之间的半形式化描述代码的方式，用于表达算法逻辑而无需遵循严格的语法。
*   **Admissible Action Space / Pseudofunctions**：在执行特定任务时，允许模型选择的一组预定义的原子操作或函数的集合。
*   **Ground Truth**：在监督学习中，指代数据集中的正确标签或标准答案，此处指由专家审核过的协议伪代码。
*   **Levenshtein Distance**：衡量两个序列之间差异的编辑距离，指通过插入、删除或替换操作将一个序列变为另一个所需的最少操作次数。
*   **SciBERTScore**：基于 SciBERT 编码器计算预测值与真实值之间余弦相似度的指标，用于评估科学文本中参数等内容的语义相似度。
*   **Chain-of-Thought (CoT)**：一种提示技术，引导模型逐步展示推理过程，以提升其在复杂推理任务上的表现。
*   **Toolformer**：一种训练 LLM 的方法，使其能够学会何时以及如何调用外部工具来增强自身能力。
